# push_swap

## Description

`push_swap` は、重複のない整数のリストを受け取り、2つのスタック(`a` と `b`)を使って昇順にソートする **Push_swap 操作の列** を、標準出力に表示するプログラムです。ソート後は、最小の数がスタック `a` の先頭に来ます。

このプロジェクトの目的は、アルゴリズムの計算量を具体的に体験することです。アルゴリズムのコストは、CPU 時間ではなく、**生成した Push_swap 操作の数**で測ります。

プログラムには4つの戦略が組み込まれており、実行時に選択できます。

| フラグ       | 戦略                          | 計算量(操作数) |
|--------------|-------------------------------|------------------|
| `--simple`   | 選択ソートの応用              | O(n²)            |
| `--medium`   | チャンクソート(√n 個の範囲) | O(n√n)           |
| `--complex`  | 基数ソート(LSD・2進数)      | O(n log n)       |
| `--adaptive` | disorder に応じて上記から選択(デフォルト) | 後述 |

`--adaptive` では、入力が5個以下のときだけ、上の3つとは別の**専用処理**(`small_sort`)を使います(後述)。

**選んだ理由:**

1. 選択ソートの応用
- 「一番小さい数を探して b に送る」という動きが、`ra` / `rra` / `pb` の操作にそのまま対応するので、実装が単純で、バグが入りにくい。
- 数が少しだけ乱れている入力では、最小値がすでに先頭の近くにあるので、回転が少なく、手数が減る。

2. チャンクソート
- 数をグループに分けて、探す範囲を狭めることで、手数を減らせる。
- 実装が短く、グループの大きさを変えて、手数を調整できる。

3. 基数ソート
- 数の大小を比べず、2進数の桁で仕分けるだけなので、実装が短い。
- 手数が、入力の並びに依存せず一定(最小・平均・最大が一致)。

4. 5個以下の専用処理
- 入力が少ないときは、3つの戦略(特に基数ソート)だと、手数が多くなりすぎる。
- 個数が決まっているので、場合分けで、少ない手数に収められる。


## Instructions

### コンパイル

```sh
make        # ./push_swap をビルド
make clean  # オブジェクトファイルを削除
make fclean # オブジェクトファイルとバイナリを削除
make re     # fclean + all
```

### 実行

```sh
./push_swap [--simple | --medium | --complex | --adaptive] [--bench] <int> <int> ...
```

- 最初の引数が、スタック `a` の先頭です。
- 操作は `stdout` に、1行に1つ表示されます。
- `--bench` を付けると、計測結果(disorder、戦略名、総操作数、操作ごとの回数)を `stderr` のみに表示します。
- 数字が1つもない場合は、何も表示しません。
- エラー(整数でない、`int` の範囲外、重複、未知のフラグ)のときは、`stderr` に `Error` と改行を表示します。

### 実行例

```sh
./push_swap 2 1 3 6 5 8

ARG="4 67 3 87 23"; ./push_swap --complex $ARG | ./checker_linux $ARG

shuf -i 0-9999 -n 500 > args.txt ; ./push_swap $(cat args.txt) | wc -l

./push_swap --medium --bench $(cat args.txt) 2> bench.txt | ./checker_linux $(cat args.txt)
```

`checker_linux` は、課題で提供されているチェッカーです。

### 動作に関する補足

- 引数は個別に渡す前提です(`./push_swap 3 2 1`)。`"3 2 1"` のように1つの文字列にまとめると `Error` になります。
- 先頭の `+`(例: `+5`)は受け付けません。
- 戦略フラグを複数指定した場合は、最後のものが有効になります。
- すでにソート済みの入力では、操作を1つも出力しません(`--bench` を付けた場合は、操作数 0 として表示します)。
- 入力が5個以下で、`--adaptive`(フラグなしを含む)のときは、専用処理を使います。`--simple` / `--medium` / `--complex` を指定した場合は、個数に関係なく、そのアルゴリズムを使います。

## Disorder(無秩序度)

disorder は、**操作を行う前に1回だけ**、次の式で測定します。

```
disorder = mistakes / total_pairs
```

ソート済みなら `0`、逆順なら `1` になります。計算に O(n²) の CPU 時間がかかりますが、Push_swap 操作ではないので、操作数には数えません。`mistakes` は、大きい数が小さい数より前にあるペアの数。`total_pairs` は、すべてのペアの数です。

## Algorithms(アルゴリズム)

すべての戦略は、最初に各値を**ランク(`index`、`0` 〜 `n-1`)**に置き換えます。ランクは「自分より小さい値の個数」を数えて求めます。これは前処理であり、操作は生成しません。

### Simple — 選択ソート、O(n²)

1. 次の処理を `n` 回繰り返す。
   1. `a` の中で、残っている最小の要素を探す。
   2. `a` を回転して(`ra` と `rra` のうち近いほう)その要素を先頭に出し、`pb` する。
2. すべて `b` に送ったあと、`pa` で全部戻す。`b` には小さい順に積まれているので、戻した `a` は昇順になる。

**計算量:**
- 「一番小さい数を探して、`b` に移す」を、数の個数ぶん(`n` 回)くり返します。
- 1回ごとに、山を回す回数は、数が増えるほど増えます。
- だから、数が2倍になると、手数は約4倍になります。これが O(n²) です。
- 追加で使う場所はありません(O(1))。

### Medium — チャンクソート、O(n√n)

1. **分配:** `b` に送った個数を `pushed`、チャンクの大きさを `c ≈ √n` とする。`a` の先頭のランクを見て、次のように操作する。
   - ランク `<= pushed` : `pb` のあとに `rb`(`b` の底へ送る)
   - ランク `<= pushed + c` : `pb`
   - それ以外 : `ra`(今回は飛ばす)
2. **回収:** `b` が空になるまで、`b` の最大要素を先頭に出し(`rb` / `rrb`、近いほう)、`pa` する。

**計算量:**
- 数を小さい順に、約 `√n` 個ずつのグループに分けて、グループごとに `b` へ運びます。
- 探す範囲が、全部(`n` 個)ではなく、今のグループ(約 `√n` 個)だけなので、1個あたりの手間が少なくて済みます。
- そのため、Simple(全部から探す)より、個数が増えたときの手数の増え方がゆるやかです。これが O(n√n) です。
- 実測では、個数が2倍になると、Simple は約4倍、Medium は約2.5〜2.7倍になりました(下のベンチマーク表を参照)。
- 追加で使う場所はありません(O(1))。

### Complex — 基数ソート(LSD・2進数)、O(n log n)

ランクの下位ビットから上位ビットへ、`⌈log₂ n⌉` 個のビットについて、それぞれ次を行う。

1. `a` の `n` 個の要素について: ビット `i` が `0` なら `pb`、`1` なら `ra`。
2. `b` の要素を全部 `pa` で `a` に戻す。

**計算量:**
- 1パスは `n` 手(`pb` または `ra`)に、`pa` が最大 `n` 回で、最大 `2n` 手。パス数が `⌈log₂ n⌉` なので、合計は O(n log n) 操作。
- 手数は入力の並びに依存せず一定(ベンチマークでも、最小・平均・最大が一致する)。
- 追加の空間は O(1)。

### Small — 5個以下の専用処理(`--adaptive` のみ)

入力が5個以下のときだけ、`--adaptive` が使う処理です(`small_sort.c`)。

- **2個:** 逆順なら `sa` を1回。
- **3個(`sort_three`):** 最大の要素の位置を調べる。
  - 先頭にあれば `ra`、2番目にあれば `rra` で、最大を末尾に送る。
  - そのあと、先頭の2個が逆順なら `sa`。
  - これで、どの並びでも、最大2手で整列する。
- **4個・5個:** 小さい順に `(n − 3)` 個を、`a` から `pb` で `b` に送る(最小値を、`ra` / `rra` の近いほうで先頭に出す)。残った3個を `sort_three` で整列し、`pa` で `b` から戻す。小さい順に送ったので、戻すと、そのまま昇順になる。

**計算量:**
- 入力の個数が最大5個と決まっているので、手数は一定(O(1))で、他の戦略の O(n²) / O(n√n) / O(n log n) の上界を超えない。
- 全順列(2〜5個)で、正しく整列することを確認した。手数は、3個で最大2手、4個で最大6手、5個で最大10手(平均 7.33 手)。

**選んだ理由:**
- 少ない入力では、基数ソートなどの手数が多くなりすぎる(`2 1 0` で10手、`5 1 4 2 3` で25手など)。
- 個数が決まっているので、場合分けで、手数を大きく減らせる。

### Adaptive — 5個以下は専用処理、それより多ければ disorder による振り分け

| 入力                | 使う戦略            | 内部手法 |
|---------------------|---------------------|----------|
| 5個以下             | small、O(1)         | 専用処理(`small_sort`) |
| 6個以上、disorder `< 0.2`          | simple、O(n²)       | 選択ソート(`--simple` と同じ) |
| 6個以上、`0.2 <= d < 0.5` | medium、O(n√n)      | チャンクソート(`--medium` と同じ) |
| 6個以上、`>= 0.5`         | complex、O(n log n) | 基数ソート(`--complex` と同じ) |

**しきい値の根拠:**
- 境界(0.2 / 0.5)は課題で指定されている。
- ランダムな並びの disorder の期待値は 0.5 になる(各ペアが逆転している確率が 1/2 のため)。500個のランダム入力で `49.93%` などが出る。したがって、ランダム入力は、およそ半分ずつ medium と complex に振り分けられる。`0.2` 未満は「ほぼ整列済み」、`0.5` 以上は「ランダム以上に乱れている」とみなす。

**各領域の選択理由:**
- **5個以下:** 専用処理。disorder に関係なく、個数だけで決める。
- **低(< 0.2):** 課題が O(n²) を指定する領域。現状は選択ソートを使う。ほぼ整列済みの入力では、最小値がすでに先頭付近にあるため回転が少なく、手数が減る。
- **中(0.2 以上 0.5 未満):** チャンクソート。ランダム入力の N ≦ 1000 では、3戦略の中で手数が最も少ない(N = 500 で平均 5,221)。
- **高(0.5 以上):** 基数ソート。手数が入力の並びに依存せず一定で、N = 5000 では3戦略の中で最少(100,196)。ただし、N ≦ 1000 のランダム入力では、medium のほうが少ない(N = 500 で、medium 5,221 に対して complex 6,784)。

**時間・空間の上界(Push_swap モデル):**
- 時間: 各領域で、O(n²) / O(n√n) / O(n log n) 操作。5個以下は O(1)。
- 空間: スタックで O(n)。追加は O(1)。

#### N を2倍にしたときの手数の倍率(平均値から計算)

| N の区間 | simple | medium | complex |
|---|---:|---:|---:|
| 50 → 100 | 3.48 | 2.48 | 2.32 |
| 100 → 200 | 3.71 | 2.49 | 2.28 |
| 500 → 1000 | 3.93 | 2.67 | 2.22 |
| **理論値** | **約 4** | **約 2.8** | **約 2.2〜2.3** |

理論値は、O(n²) なら 2² = 4、O(n√n) なら 2^1.5 ≒ 2.8、O(n log n) なら `2(1 + 1/log₂ n)` ≒ 2.2〜2.3(N = 100〜500 のとき)。実測の倍率が理論値に近いので、主張する計算量クラスは、このモデルで妥当である。

## Project structure(ファイル構成)

| ファイル | 役割 |
|----------|------|
| `main.c` | エントリポイント、戦略の振り分け |
| `parser.c`, `parser_helper.c` | 引数の解析、エラー処理、disorder の計算 |
| `push_op.c`, `swap_op.c`, `rotate_op.c`, `rev_rotate_op.c` | 11個の操作(出力とカウント) |
| `simple_sort.c`, `medium_sort.c`, `complex_sort.c` | 3つの基本戦略 |
| `small_sort.c` | 5個以下の専用処理(`--adaptive` のみ) |
| `sort_utils.c`, `stack_utils.c` | 共通の補助関数 |
| `print_msg.c` | エラーメッセージと `--bench` の出力 |
| `push_swap.h` | 型とプロトタイプ宣言 |

主なデータ構造は、`t_node`(値、ランク、next)、`t_stack`(top、size)、`t_data`(2つのスタック、操作ごとのカウンタ、選択された戦略、disorder)です。
